# 무지의 베일 — 정의로운 사회 만들기

롤스의 "무지의 베일" 사고실험을 체험하는 고등학교 사회 수업용 교실 시뮬레이션입니다. 모둠(2인 1팀)이 자신이 어떤 계층으로 태어날지 모르는 상태에서 사회 정책(세금·예산·최저임금)을 설계하고, 무작위로 정해진 역할을 통해 자신들이 만든 사회를 다시 검토합니다.

**사용하기: [who-am-i-rebuild.vercel.app](https://who-am-i-rebuild.vercel.app)**

## 화면 구성

- **학생 화면** (`/join`, `/play/:code`) — 아이패드 11인치 가로 기준. 4자리 참여 코드로 입장하고, 팀 이름은 자동으로 배정됩니다.
- **교사 대시보드** (`/teacher`, `/teacher/:code`) — 세션 생성, 학생 입장 QR·링크 공유, 단계 진행·타이머 제어, 팀별 제출 현황, 룰렛 실행, 학생 화면 미리보기, CSV 내보내기.

교사 대시보드에 들어가면 **학생 입장 QR**이 자동으로 열립니다. 학생은 QR을 스캔하거나 공유받은 링크로 기존 입장 화면을 열고, 함께 표시된 **4자리 참여 코드**를 입력합니다. 링크와 코드를 각각 복사할 수 있으며, 창을 닫은 뒤에는 대시보드 상단의 **QR 코드** 버튼으로 다시 띄울 수 있습니다.

## 수업 진행 (총 39분)

| 단계 | 활동 | 기본 시간 |
|---|---|---|
| 1 | 토론: 정의로운 사회를 한 문장으로 기록 | 5분 |
| 2 | 1차 설계: 세금·예산·최저임금 선택과 근거 제출 | 5분 |
| 3 | 역할 공개: 무작위 역할을 통해 자신의 사회 검토 | 5분 |
| 4 | 2차 토론·설계: 가상 뉴스를 읽고 정책 재검토 | 9분 |
| 5 | 발표: 1차·2차 설계 비교, 코멘트 및 성찰 기록 | 15분 |

교사가 단계를 전환하면 학생 화면도 자동으로 바뀝니다. 타이머가 0이 되어도 단계는 자동 전환되지 않으며, 교사가 시간을 조절하거나 이전 단계로 돌아갈 수 있습니다. 성찰은 발표 화면에서 학생이 이동하는 별도 화면입니다.

역할 공개 화면의 **우리 팀의 1차 설계**에서 정책 이름을 누르면 선택할 때 봤던 설명을 다시 확인할 수 있습니다. 다른 정책 이름을 누르면 설명이 바뀌고, 같은 이름을 다시 누르거나 **닫기**를 누르면 접힙니다. 교사 리허설에서도 동일하게 사용할 수 있습니다.

## 교사 리허설

교사 대시보드의 **학생 화면 미리보기**를 열면 현재 수업 단계에서 독립적인 리허설을 시작합니다. 상단의 단계 버튼이나 **이전 단계·다음 단계**로 1~5단계와 성찰을 즉시 오갈 수 있으며, 타이머 종료를 기다릴 필요가 없습니다.

리허설 안에서 정책 변경·제출, 역할 룰렛, 뉴스 확인, 발표 코멘트와 성찰 입력을 직접 해볼 수 있습니다. 입력과 선택은 리허설을 열어 둔 동안만 유지되고 실제 수업 단계·학생 응답·Firebase에는 반영되지 않습니다. **처음부터 다시**는 입력과 역할을 초기화하고 안내부터 다시 시작합니다. 미리보기를 닫았다 다시 열면 새 리허설이 시작됩니다.

기본은 컴퓨터에서 넓게 볼 수 있는 **PC 화면**입니다. **전체 화면**으로 창을 더 넓힐 수 있고 **태블릿 폭**은 학생 화면의 최대 폭인 1024px로 확인하는 보기입니다. 태블릿 폭은 화면 폭과 글자 크기를 확인하는 기능이며 실제 기기의 해상도·운영체제를 에뮬레이션하지 않습니다. 단계와 크기 조절 버튼은 스크롤하는 학생 화면 위에 유지됩니다.

## 정책과 사건카드의 연결

뉴스는 **1차 설계에서 실제 선택한 개별 정책**에 연결됩니다. 세금·예산·최저임금이 모두 선택된 경우 5장(긍정 2·경고 2·혼합 1)을 보여주며, 세 정책 분야가 모두 포함됩니다. 카드에 연결된 정책 이름을 표시합니다.

- 공동 부담형은 소득이 얼마든 같은 비율로 세금을 냅니다. 예를 들어 세율이 10%라면 소득 100만 원은 10만 원, 300만 원은 30만 원을 냅니다. 10%는 설명용 예시이며 앱이 특정 세율을 계산하거나 정하는 것은 아닙니다.
- 능력 부담형은 소득이 높을수록 더 높은 비율의 세금을 적용합니다.
- 기본 보장형은 실직하거나 아파서 생활이 어려운 사람의 식비·치료비·주거비 지원에 예산을 우선 씁니다.
- 생활 보장형은 하루 8시간씩 주 5일 일한 사람이 식비·주거비·교통비 등 기본 생활비를 마련할 수 있도록 최저임금을 올리는 방향입니다. 두 보장형은 각각 국가의 예산 지원과 일해서 받는 임금을 통해 생활을 돕는다는 차이가 있습니다.
- 공동 부담형을 선택하면 능력 부담형을 전제로 하는 ‘고소득층 세부담 확대’ 뉴스가 나오지 않습니다. 예산과 최저임금에도 같은 원칙을 적용합니다.

뉴스는 정책의 장단점을 토론하기 위한 **가상 상황**이며 실제 경제 결과를 예측한 것이 아닙니다. 전체 성향과 삶의 안정도·사회 격차도 수업용으로 단순화한 지표입니다. 전체 성향은 각 정책의 내부 점수(1~3)를 합산해 효율지향(3~4), 균형(5~7), 보장지향(8~9)으로 표시하고, 삶의 안정도에는 역할의 취약도를 함께 반영합니다. 전체 성향은 사건카드 선택에 사용하지 않습니다.

2026-10-05 이전의 성향 기반 카드가 저장된 세션은 학생의 4·5단계 화면에서 정책에 맞는 카드로 교체됩니다. 발표와 CSV도 같은 교체 기준을 사용합니다. 유효한 새 카드의 저장 순서는 새로고침 후에도 유지됩니다. CSV에는 카드 ID 대신 뉴스 제목을 내보냅니다.

## 로컬 실행 및 검증

Node.js 22.12 이상과 npm이 필요합니다. 자동 검사는 Node.js 24에서 실행합니다.

1. 저장소를 복제하고 의존성을 설치합니다.

```bash
git clone https://github.com/saam-kim/who-am-i-rebuild.git
cd who-am-i-rebuild
npm ci
```

2. `.env.example`을 `.env.local`로 복사하고 Firebase 프로젝트의 웹 앱 설정값을 채웁니다. Realtime Database를 생성한 뒤 `VITE_FIREBASE_DATABASE_URL`도 입력합니다. 환경 파일은 Git 추적에서 제외됩니다.

3. 개발 서버를 실행합니다.

```bash
npm run dev
```

`http://localhost:5173/teacher`에서 교사 세션을 만들고, 다른 탭의 `/join`에서 참여합니다. 다른 기기에서 확인할 때는 `npm run dev -- --host`를 실행하고, 같은 네트워크에서 PC의 IP 주소로 접속합니다.

```bash
npm run lint
npm test
npm run build
```

테스트는 27가지 정책 조합의 뉴스 일치·분야와 긍부정 균형, 댓글에 보고된 조합, 기존 카드 교체, CSV, 미리보기의 DB 쓰기 차단, 자동 저장 성공·실패·단계 전환을 확인합니다. GitHub Actions도 이 검사와 빌드를 실행합니다.

## 동기화 방식

Firebase Realtime Database로 **서로 다른 기기 간에도 실시간 동기화**합니다. 세션과 팀 응답은 `/sessions/{code}`, 팀의 접속 정보는 `/presence/{code}/{teamId}`에 저장합니다. 팀 식별자는 탭별 `sessionStorage`에, 교사의 최근 참여 코드와 안내 확인 여부는 기기의 `localStorage`에 보관합니다.

교사의 학생 화면 미리보기는 실제 DB에 쓰지 않습니다. 토론·발표 코멘트·성찰 입력은 500ms 동안 입력이 없으면 저장하고, 서버가 저장을 확인한 뒤 ‘저장됨’을 표시합니다. 화면 이동 시 대기 중인 입력도 저장을 시도합니다. 탭 종료나 네트워크 단절 시에는 저장 완료를 보장할 수 없으므로 완료 표시를 확인해 주세요.

## 배포

Vercel에서 Vite 프로젝트로 연결하고 빌드 명령을 `npm run build`, 출력 디렉터리를 `dist`로 설정합니다. `.env.example`의 `VITE_FIREBASE_*` 값을 Vercel 환경 변수에도 등록합니다. `vercel.json`은 React Router 경로의 새로고침을 처리하고 보안 헤더를 설정합니다. 하위 경로로 배포하려면 `vite.config.ts`의 `base`도 조정해야 합니다.

환경 변수는 **Production과 Preview에 각각 적용**해야 합니다. Production에만 등록하면 PR 미리보기에서는 수업 기능을 사용할 수 없습니다. 필수 연결 설정(API key·프로젝트 ID·DB URL)이 없는 환경에는 설정 안내와 운영 주소 링크를 표시합니다. 환경 변수를 바꾼 뒤에는 다시 빌드·배포해야 반영됩니다.

Firebase 규칙은 `database.rules.json`으로 관리합니다. 규칙 배포는 앱 배포와 별개이며, Firebase CLI로 프로젝트를 확인한 뒤 `firebase deploy --only database`를 실행합니다. 현재는 로그인 없는 교실 활동용으로 세션과 접속 정보의 읽기·쓰기를 허용합니다. 참여 코드는 접근 권한을 보장하는 비밀번호가 아니므로 학생 실명 등 개인정보를 입력하지 않는 방식으로 운영합니다.

## 코드 구조

| 경로 | 역할 |
|---|---|
| `src/routes/student/` | 학생 입장, 활동, 발표·성찰 |
| `src/routes/teacher/` | 세션 생성, 대시보드, 학생 화면 미리보기 |
| `src/data/policies.ts` | 정책 선택지와 성향 점수 |
| `src/data/events.ts` | 정책별 뉴스와 기존 카드 교체 |
| `src/data/logic.ts`, `roles.ts` | 수업용 결과 지표와 역할 |
| `src/data/csv.ts` | CSV 내보내기 |
| `src/store/` | Firebase 초기화 및 실시간 상태·트랜잭션 |
| `src/components/`, `src/index.css` | 공통 화면 요소, 저장 훅, 디자인 |
| `tests/` | 회귀 테스트 |

수정 배경과 범위는 [수정 계획](docs/policy-news-fix.md), 변경 내역은 [CHANGELOG](CHANGELOG.md)를 참고하세요.

## 기술 스택

Vite + React 19 + TypeScript + Tailwind CSS v4 + Firebase Realtime Database. Vercel을 통해 배포됩니다.

Firebase 패키지의 Firestore 하위 의존성이 오래된 `@grpc/grpc-js`를 지정하므로, `package.json`의 `overrides`에서 보안 수정이 포함된 버전을 사용합니다. 이 앱의 동기화는 Firestore가 아닌 Realtime Database를 사용합니다.
