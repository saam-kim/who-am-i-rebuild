# 연결·저장·코드 검토 (2026-10-05)

## 범위

학생 입장과 1~5단계·성찰, 교사 생성·대시보드·리허설·QR, Firebase 구독과 트랜잭션, 자동 저장, 접속 상태, 정책·역할·뉴스 계산, CSV, 브라우저 저장소, 초기 로딩을 검토했다. 화면 디자인과 수업 진행 방식은 유지했다.

## 수정한 문제

- 정책 이유를 키 입력마다 세션 전체 트랜잭션으로 저장하던 구조: 500ms 자동 저장과 팀 경로 트랜잭션으로 변경했다. 진행 중 저장의 응답을 기다린 다음 최신 입력을 보내며, 쌓인 중간 입력은 생략한다. 제출은 대기 시간을 건너뛴다.
- 서버 확인 전 제출 완료 표시: 저장 중·실패·완료를 구분하고 실패 후 다시 제출할 수 있다. 화면 전환 시 마지막 대기 입력도 저장한다.
- 팀 트랜잭션과 전체 세션 변경에서 원본 중첩 객체를 직접 수정하던 문제: 복제한 값에 변경을 적용한다.
- PIN 존재 확인과 생성 사이의 경쟁: 생성 자체를 트랜잭션으로 처리하고 충돌 시 최대 30회 재시도한다. 기존 수업을 덮어쓰지 않는다.
- 읽기 구독 취소 오류 후 무한 로딩: 오류 상태와 다시 연결하기를 표시한다. 서버 연결이 6초 이상 지연되면 안내하고 재연결 시 안내를 닫는다.
- 접속 상태 구독 누수와 오프라인 하트비트 누적: 화면 종료 시 구독을 해제하고 이전 쓰기가 끝나기 전 중복 요청을 보내지 않는다.
- 교사 단계·타이머·역할 공개의 처리되지 않은 Promise 오류: 중복 조작 방지와 실패 안내를 추가했다. 현재 단계 재선택이 타이머를 초기화하지 않도록 했다.
- 룰렛 저장 실패 시 버튼이 계속 비활성화되는 문제: 오류 안내 후 재시도할 수 있게 했다.
- 교사 팀 상세 모달이 열린 시점의 데이터에 머무는 문제: 최신 구독 데이터를 표시한다.
- 발표 결과가 1차 설계를 사용하고 CSV는 2차 설계를 사용하는 불일치: 둘 다 2차 설계를 우선 사용한다.
- 성찰 중 교사가 단계를 되돌려도 학생이 성찰에 남는 문제: 수업 단계 복귀를 반영한다.
- 브라우저 저장소의 쓰기만 실패하는 경우 팀 ID를 읽지 못하는 문제: 메모리 대체 저장값을 우선 읽는다.
- CSV 수식 실행과 CR 줄바꿈: 입력을 텍스트로 보호하고 CR도 인용한다.
- 교사 전용 대시보드·QR 코드를 학생의 초기 로딩에서 분리했다. 화면 모듈 로딩 오류에도 재시도 화면을 표시한다.

## 검증과 한계

빌드·린트 및 테스트 70개를 통과했다. 저장 실패, 지연 응답 순서, 오래된 대기 입력 생략, PIN 충돌, 없는 팀 저장 차단, 연결 안내, 구독 해제, 룰렛 재시도, 저장소 대체, 결과 계산과 CSV 보호를 확인했다. `npm audit --omit=dev`의 알려진 취약점은 0개였다. 학교 Wi-Fi·기기 조합의 실제 지연 시간이나 동시 접속 부하를 측정한 결과는 아니다. 이번 검토를 위해 운영 수업 데이터에 쓰기나 부하 테스트를 하지 않았다.

Firebase 웹 SDK의 오프라인 쓰기는 브라우저 세션을 넘어 영구 보관되지 않는다. 연결이 돌아오기 전에 탭을 닫으면 미전송 입력이 유실될 수 있으며, 화면 안내에 반영했다. [Firebase 오프라인 동작](https://firebase.google.com/docs/database/web/offline-capabilities), [트랜잭션과 저장](https://firebase.google.com/docs/database/web/read-and-write)을 기준으로 처리했다.

## 별도 개선이 필요한 권한 구조

저장소의 `database.rules.json`은 `/sessions`, `/presence`의 읽기·쓰기를 공개 허용한다. 앱에도 교사 인증이나 팀별 쓰기 권한 분리가 없다. 따라서 화면 버튼을 숨기는 것만으로 다른 수업의 읽기·변경을 막을 수 없다. 이는 확인된 설계상 한계이며, 운영 DB에 현재 어떤 규칙이 적용됐는지는 이번 코드 검토에서 인증된 관리 API로 확인하지 않았다.

해결하려면 교사·학생 신원 및 세션 소유권을 도입하고, 기존 수업의 소유권 전환과 Firebase 규칙 배포를 함께 진행해야 한다. 단순히 현재 규칙을 차단하면 사용 중인 수업이 연결되지 않으므로 이번 배포에서 규칙 파일이나 운영 DB 권한을 변경하지 않는다. 공개 배포 앱의 후속 우선순위는 이 권한 분리다.
